IE Báo cáo máy

Update the MACHINE DATABASE from layouts and costing, analyse machine shortage by day, prepare changeover machines. Runs in Chrome or Edge, needs no network, sends no data anywhere.

1. Introduction

The tool does three main jobs, matching the tabs at the top of the page:

TabUsed for
DataChoose the MC Report, the Master plan, the layout folder, the data folder of Layout Check, and type your name. A ✓ shows when everything is loaded.
Update databaseScan layouts, review changes, Save MACHINE DATABASE (the save bar only shows on this tab). The number on the tab = items to review.
Shortage & prepRank the risk of machine shortage, detail by day, send to IE Tech for review, close the report, export Excel.
Remaining shortageThe shortage left after IE Tech's review (horizontal tables, choose machine group / PU), the actions to solve it (rent, buy, borrow, take back, move the plan) recorded right under the table of every short machine group with an instant result, and the summary card (section 6).
Variation noticesNotices from IE Tech. The number on the tab = notices not handled yet.
ActivityHistory of the prep-machine actions by machine group and by line.

Back to the home page: click Home at the top right. Resize columns: in every table, drag the right edge of a column header to change the width (the text in the table wraps); double-click that edge to go back to automatic.

At the top right there are three role buttons (Consolidator / IE Tech / Supervisor) and the language button VI / EN. The IE Tech role sees only the "Review prep" screen (section 5); the Supervisor role only views "Remaining shortage" (section 6).

A style is complete only when an IE officer saves Pass/Accept in Layout Check. IE Báo cáo máy never writes "Pass"; it only writes an "Approved" note.
The pictures in this guide use synthetic demo data (styles DMO26-…, lines A, B, K, J, D, E), not company data. Screenshots show the Vietnamese screen; switch the tool to English with the EN button.

2. One-time setup in the MC Report

  1. The MACHINE DATABASE stays as the table Table1. Do not rename it.
  2. Data > Get Data > From Other Sources > Blank Query > Advanced Editor, paste the content of PowerQuery\costing_query.pq, edit the 4 setting lines (PlanFile, CostingFile, Server, Database) > Done > rename the query to COSTING PROPOSAL > Close & Load To… > Table > New worksheet > rename the sheet to COSTING PROPOSAL.
  3. Data > Get Data > Query Options > CURRENT WORKBOOK > Privacy > choose "Ignore the Privacy Levels".
  4. First refresh: enter the SQL account (choose Database, the read account used by the costing macro); in the "Native database query" dialog choose Run.

Optional: PowerQuery\machinedb_latest_query.pq reads the MACHINE DATABASE from the latest saved file in a fixed folder (see section 3, step 4b).

The MC Report used with the tool needs the sheets: MACHINE DATABASE, MACHINE GROUP (required); COSTING PROPOSAL (if missing, costing is skipped); MACHINE BY LINE, MC STATUS, PU LIST (for the Shortage & prep tab).

3. Update the MACHINE DATABASE (weekly)

Before you start: open the MC Report, Data > Refresh All > Save.

Step 1: Input data (Data tab)

  1. Open IE_BaoCaoMay.html with Chrome or Edge.
  2. MC Report… (remembered): choose the MC Report file. The tool remembers this file for the following weeks.
  3. Choose Excel files… (remembered): choose this week's Master plan, last week's file and CheckMc (you can pick several files at once; the tool recognises each file by its sheet names and remembers these files). The button "or choose Excel files… (not remembered)" is for when you do not want them remembered.
  4. Choose layout folder… (remembered): the root folder that holds layouts (sub-folders are scanned too; the folders Old layout, /old/, backup are skipped). If Chrome asks "Upload", choose Upload (the data is only read on this computer). "or choose the old way" selects without remembering.
  5. Connect Layout Check data folder… (optional but recommended): choose the shared data folder, click Allow (view and edit). Type your Name.
From the next time: the tool reconnects the remembered MC Report, Excel files, layout folder and data folder by itself when the browser still allows it; if the browser needs to ask for permission, click on the page once (or "🔁 Reconnect"). IE Tech and Supervisor share these folders. Each week you only need to choose the new Master plan again if its file name is different. The previous scan state comes from the data folder; you do not need to choose "the file saved last time". The first time you can also choose CheckMc.xlsm to compare with the latest CheckMc scan.

Step 2: Scan layouts (Update database tab)

Click Start. The tool scans layouts first; styles without a layout use costing. The progress bar shows the number of files scanned. The scan works like the CheckMc macro (RunWeeklyIncrementalScan); for Man-Machine files only Man-Machine-Ass/Prep are used; hidden sheets and sheets named "F T S C" / "F-S-T-C" are not scanned.

Step 3: Review and save

The scan result is split into cards (click a card to see it):

CardMeaning
To reviewStyles with new data or data different from the database; sorted by loading date. Labels: New, Layout changed, Costing → Layout, Costing, Manual data, From Layout Check, Waiting for layout fix.
Still missingStyles in the plan that have no layout, no costing and are not in the database. How to handle is written in the last column.
Data issuesTo be fixed at the source (for example a machine code that is not in MACHINE GROUP; a row pasted twice in the database can be marked to keep one copy).

Confirmed to keepStyles for which you chose "Keep current data" and confirmed it (see below). The card only shows when there are confirmed items.
Checked (Layout Check)The IE officer saved Pass/Accept, the layout did not change and the database matches: no review again.

  • Every layout file is one option, with the file's modified date. Below are the sheets that have a machine table (hidden sheets are not included): by default every Man-Machine sheet is ticked, otherwise the first sheet that names the style. Tick / untick to add sheets together; the machine count and the comparison update at once.
  • Tick ✓ row by row, or click Approve all items shown. Clear selection unticks everything.
  • Quick filters: New, Costing, Manual data, and the search box for style/file.

When you have chosen, click Save MACHINE DATABASE in the bottom bar. The file is saved as MACHINE_DATABASE_yyyymmdd_hhmm.xlsx.

Keep current data and confirm keeping

When a layout is new or different but you want to keep the database as it is (for example manual data that an IE already checked, or a layout that is not final), do this:

  1. In the Data source column of the style, choose Keep current data (the last line of the list).
  2. Tick the ✓ box at the start of the row. The bottom bar shows "1 keep confirmation" and the button Confirm keep (1).
  3. Click Confirm keep. You can also click Save MACHINE DATABASE: the ticked keep items are remembered at the same time.

The style moves to the Confirmed to keep card and does not show again under "To review" in the following scans. It shows again only when one of two things changes:

  • The content of the layout changes (a different machine code or quantity): the note says "The layout changed after … confirmed keeping the current data".
  • The style's data in the database changes (for example someone updated the machine count): the note says "The database changed after … confirmed keeping the current data".

When it shows again, the old confirmation is cleared; to keep it again, confirm again. Only re-saving the file, a new modified date or a layout format change does not make the style show again.

  • The confirmation is stored in data\machinedb\keeps.json (shared with the people using the same data folder). If the data folder is not connected, the confirmation is stored only in this computer's browser.
  • You cannot confirm keeping when the style has no current data (a new style): the ✓ box is locked because there is nothing to keep.
  • "Approve all items shown" does not confirm keeping automatically; tick each style.

Shortage uses the changes just approved

After you click Save MACHINE DATABASE, the Shortage & prep tab calculates the machine demand including the changes just approved; there is no need to wait for pasting into Table1 and Refresh All. The line "Demand calculated from" says so: "incl. N changes just approved (the database in the MC Report is not updated yet)".

  • The detail table that was open is cleared; click Open detail for selected groups again to see the new numbers.
  • A proposal sent to IE Tech in the meantime records the basis; IE Tech sees the line "Proposal based on a database that includes N changes just approved…" above the table.
  • You still must paste into Table1 and Refresh All (step 4). When the updated MC Report is loaded again, the note disappears by itself and the numbers do not change.

Step 4: Put the data into the MC Report

Choose one way:

  1. Paste the MACHINE DATABASE sheet of the file just saved into the table Table1 (replace all rows); or
  2. Recommended: save the files in a fixed folder and use machinedb_latest_query.pq.

Then Refresh All in the MC Report. Keep the file just saved (the scan state is also written to the data folder if Layout Check is connected).

A style that is "Approved" in IE Báo cáo máy but not yet in the database will remind you: "check that it was pasted into Table1".

4. Shortage and prep machines

The Shortage & prep tab needs an MC Report with the sheets MACHINE BY LINE, MC STATUS, PU LIST and a loaded Master plan. You do not need to scan layouts first. Only working days are counted (no Sundays).

4.1 Rank the shortage risk

  1. Set From date, Weeks, Common margin % (default 10%). By default only machine groups that may be short are shown; tick "Show all groups" to see everything.
  2. Available = the column "MC used for PDN" of the MC STATUS sheet, summed per machine group. Peak demand = the production demand per day plus the common margin. A negative Lowest left (red) is a shortage risk.
  3. Tick the machine groups to look at, enter the Prep ratio % (default BT1M 50%, other groups 0) and the Days (default 3). Save prep ratio to share it with everyone.
  4. Click Open detail for selected groups.

Available detail: below the "Available" line are the columns of the MC STATUS formula: plus signs (Machine in house, RENT, BORROW) and minus signs (BROKEN, LENDING, TRA, PDC-Sample, Strapline, Line borrow, ATH transfer, PU3-Sample, PU2 keep…). If the formula changes, the tool reads the signs again.

4.2 Detail by day

4.3 Prep rules

  • A new style that loads on a line (it did not run on the previous working day) needs ROUNDUP(ratio × machines of that style) during N working days before the loading date (Sundays skipped).
  • No prep when the two styles share a layout file, or are in the "Same layout" list, or IE Tech removes it.
  • The first day of the plan has no prep (the style is already running). For a line that works on Sunday: Sunday has production but the prep days still skip Sunday. Every changeover has only one prep row.
  • Prep is counted only for the selected machine groups.

4.4 Send to IE Tech

Click Send prep to IE Tech: the proposal is written to data\prep\proposals. IE Tech only sees the latest proposal of every machine group.

5. IE Tech: review prep

5.1 Connect

  1. Click the role button IE Tech. First time: Choose data folder… (the shared data folder) and Choose layout folder… (the root folder that holds layouts). The browser remembers these two folders. You can type the network path of the layout folder to open the original file in Excel.
  2. Type your Name, choose your PU (taken from PU LIST and the proposals sent) and type your Lines: type the start of the line codes separated by commas (K = every K line; K,J; K05). Empty = all lines.

5.2 Review row by row

On every prep row (yellow):

ButtonEffect
✔Keep (one click).
✖Remove (one click, no reason needed).
✎ or click the rowOpens the right-hand panel to adjust.

5.3 The adjust panel on the right

  • Prep machines: the number IE Tech decides.
  • Layout quantity: if different from the database, the prep number is recalculated from it and the Consolidator automatically receives a notice in the Variation notices tab.
  • Loading date: the real date; the prep days move back with it (N working days before, Sundays skipped) and the production on the line moves too. The card shows "loads 15/11 → 18/11". A row not reviewed yet counts as "Keep" when you change the date.
  • Prep days.
  • Save, ✖ Remove prep, Same layout (remove and remember): remembered by style pair (previous style → next style) and applied at once to every machine group and every line with the same pair; when the Consolidator clicks "Open detail" it is read again. To prep one specific row again: click Keep or Adjust on that row (it has priority).

5.4 Find and view the layout

The Find layout box (the file list of the layout folder, remembered for 8 hours; ⟳ Rescan to refresh). Empty = suggestions by file name (Same style > Style without size > Same article); type part of a name to search. Click a file to see the machines of the machine group being viewed ("Show all machines of the layout" to see all), one column per sheet, with the file's modified date.

5.5 Change the end date of the running style

On the row of the running style of every line (the style running on the first day of the table) there is the text "ends dd/mm" and a ✎ button. Clicking ✎ opens a date box with a calendar (like the loading-date box of a prep row): choose the date and click Save; click Per plan (or pick exactly the plan date) to return to the plan. The running style stops after that date (if later than the plan it keeps running with the last machine count); the next style loads on the next working day and its prep moves; it applies to every machine group of the line.

5.6 Finish the review

When you have reviewed the scope you are viewing (PU, your lines, all machine groups), click ✔ Finish review. If rows are not reviewed yet, the system warns the number of rows and lines; you can still finish (those rows keep the proposed number). You can finish again after reviewing more.

Decisions are kept for next week when the style sequence on the line does not change (same line, previous style, next style, machine group), even if the dates change. If the machine count of the next style in the database changes, the row goes back to "Waiting".

6. Remaining shortage, actions

After IE Tech's review, a machine group that is still short needs a decision: rent, buy, borrow or move the plan with PPC. This screen gathers the numbers for the decision maker (Supervisor) and lets the Consolidator record the actions.

6.1 Open the screen

  • Consolidator: the tab Remaining shortage (the data folder must be connected; the number on the tab = machine groups still short).
  • Supervisor (view only): click the role Supervisor → Choose data folder… (or "🔁 Reuse") → choose the shared data folder. No MC Report or Master plan needed.

The numbers come from the latest proposal of each machine group and IE Tech's decisions, using exactly the calculation of the IE Tech table. Click Refresh to read again when someone has just saved.

6.2 View the numbers: horizontal table by day

  • Choose machine groups and PUs: click a machine group (or PU) to view only that one; click more to add or remove; All machine groups / All PUs clears the filter. Clicking a row of the summary table also selects that machine group. Choosing a PU only filters the PU rows; "Available" and "Left" are always for the whole machine group (the available machines are not split by PU).
  • Short days only (default): every machine group shows from its first short day to its last short day. If there is a period with enough machines between two short periods, the days with enough machines in between are still shown. Whole plan: shows all the days of the proposal.
  • The rows of every machine group: Production / Preparation / Total per PU, Total used, Available, Left (now), the action rows, then Left after confirmed actions and Left incl. planned (the last two only show when there are actions).
  • See the lines and styles of each PU: click a PU row (the ▸ sign) to show the lines and styles of that PU, like the IE Tech table: one row per style with the machines per day, plus the "prepare" rows. The button Show all styles opens every PU of the machine group. The button ⬇ Export Excel on every machine group saves that table as a formatted Excel file (header, frozen first columns/rows, short cells with a light red background, style rows grouped so they can be collapsed) with formulas (Production = sum of the styles, PU total, Total used, Left = Available − Total used, Left after actions…), so when you edit a number in Excel the total rows recalculate. Contents: the whole plan, every PU, line, style, area, action.
  • Areas holding machines: under the "Left (now)" row are the areas that take machines out of production according to MC STATUS (for example lending, broken, TRA, sample room): one row per area with the number of machines it holds (this number is already taken off "Available"). Click ↩ Take back on an area row to open the action box with the type "Take back from area".
  • Negative numbers (shortage) have a light red background and red text so they are easy to see; this also applies to the "Left" row in IE Tech's table.
Column of the summary tableMeaning
Days shortThe number of working days with "Left" < 0 out of the days of the proposal.
Worst gapThe machines short on the worst day (with the date). From – to: the first and last short day.
After confirmed actionsThe shortage left when only the confirmed actions are counted.
Incl. plannedThe shortage left when the planned actions are counted too.
Not reviewedThe number of prep rows IE Tech has not reviewed (the numbers may still change).

6.3 Actions: every short machine group has its own box, the result shows at once

Under the table of every machine group that is still short there is a box Action for <machine group>. Just choose the type and enter the machines or dates: the "Try" rows in the table above and the line "Result now" (worst gap and days short, before → after) update at once, nothing is saved yet. Until you enter something the table has no try rows. Only the Consolidator has the Add action button (type your Name in the Data tab first); the Supervisor can try but cannot save.

TypeEffect on the numbers
Rent, Buy, BorrowAdds machines of the machine group in the date range entered (filled automatically from the biggest shortage and the short period). You can write the receiving PU (optional) so the summary card shows it by PU.
Take back from areaChoose the area (the machines it holds are written in brackets), the number of machines to take back (not more than the area holds) and the date range: these machines are added to "Left" in that range and the area row goes down by the same amount (when confirmed). The area name is written in the action and in the summary card.
Delay planChoose the line, the style and the new loading date (a Sunday moves to a working day; the box says "+n working days"). The whole line moves: that style and every style after it load later; the previous style keeps running; the prep moves. It really changes every machine group that uses the line; the instant result tells how much the other machine groups change.
OtherA note is required. If you enter machines (+ or −) and a date range, they are added/subtracted as above; otherwise it is only recorded.
Delaying the plan may not solve the shortage (for example the peak use falls on another day, or the days short increase because the previous style runs longer). Read the line "Result now" (worst gap and days short) before you suggest it to PPC.
  • Planned = not sure yet; Confirmed = the machines are there / PPC agreed to the delay. The two states are counted in two separate rows ("after confirmed actions" and "incl. planned").
  • Every action is a row in the horizontal table and shows its real change per day. The button ✎ edits, ✔ confirms (Planned → Confirmed), ✖ cancels (the row is struck through and has no effect).
  • A delay that is already in the new plan: when the new MC Report / Master plan already loads the style on or after the new date, the action gets the label "Already in the plan" and is not counted any more (to avoid moving twice).
  • Every change is written as a file in data\prep\actions and also shows in the Activity tab (type "Shortage action").

6.4 The summary card

When every action is confirmed (no Planned action left) and there is at least one action, the screen creates the card Summary of the shortage actions: four tiles (machine groups with enough machines, groups for IE to check further, confirmed actions, machine-days short before → after) and one card for every machine group (shortage before → after, progress bar, list of actions). The shortage by PU is inside the machine group card: every PU shows the machines it uses on the worst day, its share and its status; click a PU to see its lines, styles, the production/prep machines of that day, the machines per short day and the PU's actions (click again to close). A machine group or PU without actions that is still short says "IE check further"; a machine group still short after the actions says "Still short −x: IE check further". The button Export Excel saves the card as a file.

7. Close the report, export Excel

Go back to the Consolidator role, the Shortage & prep tab, click Open detail for selected groups to see IE Tech's decisions (labels Kept, Adjusted 1→2, Removed, Same layout — skipped, by layout qty, "date set by IE Tech").

Close the report

Conditions: the data folder is connected in the Data tab and your name is typed.

  1. Click 🔒 Close report…. The table per PU shows: the number of prep rows, not reviewed, Keep / Adjust / Remove, IE Tech finished (who, when), unhandled notices. Refresh to read again.
  2. The red line at the bottom tells what is still open: rows not reviewed, unhandled notices, PUs not finished.
  3. Type a note (optional) and click 🔒 Close report. If something is still open the system warns you; you can still close.
  • Closing does not lock the data. If IE Tech or the Consolidator changes something afterwards, the row shows "N changes after closing"; then close again.
  • The closing record is stored in data\prep\closed.

Export Excel

Click Export Excel (after "Open detail"): one sheet per machine group coloured like the current detail sheet; the sheet PREP BY PU in exactly the TTL DEMAND BY PU layout (Combine.MACHINE | PU | day) to add to the report; the sheet NOT REVIEWED lists the rows IE Tech has not reviewed; the sheet STATUS (who closed, when, the note, the table per PU). The file name has CHOT (PREP_DEMAND_CHOT_…) only when the report is closed and nothing changed afterwards. Removed prep rows are exported as 0.

8. Variation notices and Activity

Variation notices from IE Tech

When IE Tech enters a "Layout quantity" that differs from the database, a notice shows in the Variation notices tab. Check the layout, fix the database in step 3 if it is right, then click Database fixed or Not correct. When the database matches IE Tech's number, the status column says "Database matches" by itself. IE Tech sees the result in the table "Notices I sent".

Activity

Contents: proposals sent, IE Tech's decisions (Keep, Adjust, Remove, Same layout, loading date change, prep days, layout quantity, end date change), notices and answers, finished reviews, closed reports, database approvals. The data folder must be connected; click "⟳" to read again.

  • Filters: From date / To date (default the last 30 days), PU, person, action, line, style or text; the machine-group buttons at the top show only that group.
  • Three views: Detail, By machine group, By line (counts Keep, Adjust, Remove, Same layout, Notices, Finished and the latest action; click a row to see the detail).
  • Export Excel: three sheets LOG, BY MACHINE GROUP, BY LINE following the current filters.

Database dataOnly the rows with the latest date of each style are used.
The latest decision appliesThe tool reads again the exact file and sheet of the Layout Check record: machines in the file = record and database = record → "Checked"; the file was edited after the check → "To review", IE re-checks; a file different from the one the IE checked → "Data issue: the layout file differs from the file the IE checked".

Numbers right after savingThe shortage report also counts the changes just approved (with a label), even if the MC Report is not updated yet.

10. Saved files and the data folder

The file MACHINE_DATABASE_yyyymmdd_hhmm.xlsx has these sheets:

SheetContents
MACHINE DATABASEThe whole database after applying the approved changes (paste into Table1).
CHANGESThe change log (old, new, source, file, approval date).
EXCEPTIONSData issues and missing styles.
LAYOUT DATA, NEW CHANGED, SCAN STATEThe current layout data, the files that are new/changed in this run, the scan state.

The data folder is shared with Layout Check: machinedb\scanstate.json (hash of each layout file), validations\*.json (Layout Check decisions), approvals\*.json ("Approved" notes, not counted as a check), prep\ (proposals, reviews, shared, notices, noticeres, complete, closed, lineends, actions, rules.json), machinedb\keeps.json (keep confirmations).
